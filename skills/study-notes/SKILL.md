# 배움노트 정리 (study-notes)

Claude Code와 OpenAI Codex 어디서나 같은 방식으로 동작한다. Claude Code에서는 `/study-notes`, Codex에서는 `$study-notes`로 부른다.
`/study-notes 3`, `$study-notes 기초`처럼 설명 수준을 붙여 부르면 그 단계로 쓰고, 다음 실행을 위해 기억한다.

## 가장 중요한 원칙: 요약이 아니라 "재강의"

- 대화는 **주제를 찾는 계기**일 뿐이다. 노트 본문은 대화 문장을 발췌·축약하지 않는다. 그 개념을 **처음 배우는 학생에게 가르치듯 처음부터 다시 설명**한다.
- 독자는 사용자가 고른 **설명 수준**(아래 5단계)의 학습자다. 고르기 전에는 2단계 입문(부트캠프에 막 들어온 비전공자)으로 쓴다. 바이브 코딩 중 AI가 빠르게 지나간 개념을 나중에 혼자 읽고 이해하는 것이 목적이다.
- 대화에서 AI가 설명 없이 쓴 전문 용어(마이그레이션, 의존성 주입, 스트리밍, 체크포인트, 레이어 규칙 등) 가운데 독자 수준에서 낯선 것은 **대화에 설명이 없었더라도 노트에서는 반드시 풀어서** 설명한다. 어디까지 풀지는 아래 수준 표를 따른다.
- 주제 하나의 분량은 A4 반 쪽~한 쪽. 짧은 메모가 아니라 읽고 이해할 수 있는 교재 분량으로 쓴다.
- 쓰고 나서 스스로 확인: "이 노트만 읽은 그 수준의 학생이 같은 상황을 혼자 재현하거나 남에게 설명할 수 있는가?" 아니면 더 쓴다.

## 설명 수준 (5단계)

배움일기 코치 앱의 '답변 수준'과 같은 다섯 단계다. 단계 이름·대상·방식의 기준은 스크립트의 `LEVELS`다.

| 단계 | 독자 | 쓰는 방식 | 주제 고르기 |
|---|---|---|---|
| 1단계 왕초보 | 컴퓨터·IT 용어가 낯선 분 | 중학생도 아는 쉬운 말. 일상 비유로 큰 그림을 먼저 보여 주고, 전문 용어·영어 약어는 나오자마자 쉬운 말로 푼다. 한 번에 개념 하나씩 짧은 문장으로. 코드는 꼭 필요할 때만 아주 짧게, 한 줄씩 말로 풀이. 어린아이 대하듯 하지 않고 성인을 존중하는 존댓말 | 대화에 나온 기초 개념(터미널, 폴더 경로, 설치 등)까지 모두 다룬다 |
| 2단계 입문 | 비전공으로 막 입과한 분 | 쉬운 말로 쓰되 현업 핵심 용어는 알려 주고, 처음 나올 때 한 줄로 뜻을 푼다. 비유로 감을 잡은 뒤 짧은 예시 코드와 주석으로 잇는다. 왜 필요한지와 흔한 실수를 짚는다 | 처음 나온 개념은 기초라도 다룬다 |
| 3단계 기초 | 변수·함수·조건문을 익힌 분 | 아는 기본 용어는 그대로 쓰고 새 개념만 한두 줄로 푼다. 작은 단계로 나눈 예제와 단계마다 그렇게 되는 이유, 비슷한 개념과의 차이, 자주 하는 실수와 해결 방법 | 변수·함수·조건문 수준의 기초 주제는 뺀다 |
| 4단계 실전 | 웹 프로젝트를 만드는 분 | 변수·함수·API·HTTP 같은 기본 용어는 풀지 않는다. 동작 원리, 설계 이유, 대안과 장단점 중심. 실무에 가까운 코드, 주의할 점, 디버깅 방법 | 기본 웹 개념 주제는 빼고 설계 결정·문제해결 위주로 줄인다 |
| 5단계 심화 | 전공자·실무 경험자 | 기초 설명 생략, 정확한 기술 용어로 간결하게. 내부 동작, 성능·보안·확장성 트레이드오프, 엣지 케이스, 근거가 되는 공식 문서·표준, 필요하면 대안 설계 비교 | 내부 동작·트레이드오프·설계 결정처럼 깊이 있는 주제만 남긴다 |

- 모든 단계에서 "요약이 아니라 재강의" 원칙과 템플릿의 소제목 구조는 같다. 단계가 높을수록 주제 수가 줄고 한 주제를 더 깊게 쓴다.
- 고르기 전 기본값은 2단계다. v1.3까지의 노트와 같은 수준이다.
- 노트에는 수준을 이렇게 표시한다(템플릿 참고): frontmatter `title` 끝의 ` · 3단계 기초`와 `level: 3`·`level_name: 기초`,
  H1 제목 끝의 ` · 3단계 기초`, H1 바로 아래 인용문 첫 줄 `> 설명 수준: 3단계 기초. 변수·함수·조건문을 익힌 분에게 맞춰 썼어요.`
  그다음 `>` 빈 줄을 두고 요약을 잇는다.
- H1과 인용문 사이에는 다른 문단을 넣지 않는다. 노트를 올리는 학습 관리 앱이 H1 바로 뒤의 인용문을 노트 요약으로 읽는다.

## 준비: 세 변수를 먼저 정한다

아래 명령의 `$PY`, `$SKILL_DIR`, `$AGENT`는 실행 전 실제 값으로 바꾼다.

- `$PY` = 파이썬 실행 명령. macOS/Linux는 `python3 -I`, Windows는 `python -I` (없으면 `py -3 -I`). 3.10 이상.
- `$SKILL_DIR` = **이 SKILL.md가 들어 있는 폴더**. 홈 디렉터리는 `~` 대신 `$HOME`으로 쓴다 (bash와 PowerShell 모두에서 풀리고, PowerShell은 외부 프로그램 인자의 `~`를 풀지 않는다).
  - Claude Code 플러그인: `${CLAUDE_PLUGIN_ROOT}/skills/study-notes`
  - Claude Code 직접 복사: `$HOME/.claude/skills/study-notes`
  - Codex: `$HOME/.codex/skills/study-notes` (`CODEX_HOME`을 바꿨다면 `$CODEX_HOME/skills/study-notes`)
- `$AGENT` = 지금 실행 중인 도구. Claude Code면 `claude`, Codex면 `codex`. 스크립트가 이 값으로 어느 쪽 대화 기록을 읽을지 정한다.

Windows 주의: 명령은 Git Bash 또는 PowerShell에서 실행한다 (cmd.exe는 `$HOME`, `$PWD`를 모른다). 경로 구분자는 `/`를 써도 된다.
Git Bash의 `$PWD`가 `/c/Users/...` 형태여도 스크립트가 `C:\Users\...`로 바꿔 처리한다. 노트는 `%USERPROFILE%\StudyNotes`에 생긴다.

Codex 주의: 노트 폴더 `$HOME/StudyNotes`는 작업 폴더 밖이다. 노트를 쓰거나 `commit`을 실행할 때 샌드박스가 막으면 쓰기 승인(escalation)을 요청한다. 기록 읽기(`~/.codex/sessions`, `~/.codex/state_*.sqlite`)는 읽기 전용이다.

## 절차

1. **세션 id 확인**
   - Claude Code: 시스템 프롬프트의 Scratchpad directory 경로 마지막 디렉터리명이 현재 세션 id다 (예: `b4a801d7-…`). 찾을 수 없으면 `--session`을 생략한다.
   - Codex: 스레드 id가 프롬프트에 없으므로 `--session`을 **생략**한다. 스크립트가 스레드 목록 DB에서 "이 작업 폴더에서 사용자가 연 가장 최근 스레드"를 고른다. 이후 `commit`에는 extract 출력의 `session` 값을 그대로 넘긴다.
2. **설명 수준 정하기**
   - 사용자가 부르면서 단계를 말했으면(`/study-notes 3`, `$study-notes 기초`, "4단계로 정리해 줘" 등) 그 값을 3번 증분 추출의 `--level`로 넘긴다. 넘긴 값은 다음 실행을 위해 기억된다.
   - 말하지 않았으면 기억된 단계를 본다:
     ```bash
     $PY "$SKILL_DIR/scripts/study_notes.py" level
     ```
     `level_source`가 `saved`면 그 단계로 쓴다(`--level`은 생략).
   - `unset`이면 처음 실행이다. 출력의 `levels`로 다섯 단계 표(단계·대상·방식)를 보여 주고 "번호(1~5)로 골라 주세요. 고르기 전에는 2단계 입문으로 씁니다."라고 물은 뒤 **멈추고 답을 기다린다**. 보기가 다섯 개라 선택지 도구(보기 최대 4개)는 쓰지 않고 채팅으로 묻는다. 답을 받으면 그 값을 `--level`로 넘긴다.
   - 사용자에게 물을 수 없는 실행(예약 실행 등)이면 2단계로 쓰고, 보고할 때 바꾸는 방법을 알린다.
3. **증분 추출**:
   ```bash
   $PY "$SKILL_DIR/scripts/study_notes.py" extract --agent $AGENT --cwd "$PWD" --session <세션id> [--level <단계>]
   ```
   stdout JSON의 `new_messages`가 0이면 "정리할 새 대화가 없습니다"라고 알리고 끝낸다.
   `delta_path`의 파일을 읽는다. 길면 나눠 읽는다. `suggested_file`이 이번에 쓸 노트 경로, `run_no`가 노트 번호다.
   `level_label`(예: `3단계 기초`)·`level_audience`·`level_style`이 이번 노트의 설명 수준이다. 단계 값이 틀리면 스크립트가 고를 수 있는 값을 알려 주고 멈춘다.
4. **주제 뽑기** (델타 전체를 읽은 뒤):
   - 포함: 처음 등장한 기술 개념, 오류·막힘과 해결 과정, 실행한 핵심 명령어·코드, 설계 결정과 그 이유, 워크플로·도구 사용법(스킬, 에이전트, 훅 등)
   - 제외: 인사, 단순 진행 보고, 같은 내용의 반복, 비밀값(`.env` 내용, 토큰, 키, 이메일)
   - 중복 방지: index.md 전체를 읽지 말고 아래 순서로 후보만 좁힌다 (토큰 절약).
     1. **찾기**: 주제마다 키워드 2~3개(한글 용어, 영문 용어, 동의어)를 한 번에 검색한다.
        `grep -iE "체크포인트|checkpoint|증분" "$HOME/StudyNotes/index.md"`
        (PowerShell은 `Select-String -Path "$HOME/StudyNotes/index.md" -Pattern "체크포인트|checkpoint|증분"`)
     2. **판단**: 걸린 행의 제목·태그·요약 열을 보고 이번 주제와 같은 내용인지 정한다. 대부분 여기서 끝낸다.
     3. **확인 (드물게)**: 요약만으로 애매할 때만, 링크된 노트에서 그 `## N.` 섹션 하나만 읽는다. 파일 전체는 읽지 않는다.
        `awk '/^## 3\. /{p=1;print;next} p&&/^## [0-9]+\. /{exit} p' "<노트 경로>"`
     - 겹치면 새로 배운 부분만 "심화" 성격으로 쓰고 첫 줄에 기존 노트 링크를 건다. 새로 배운 게 없으면 그 주제는 뺀다.
   - **수준에 맞게 거른다**: 위 수준 표의 '주제 고르기' 기준을 적용한다. 그 단계 독자가 이미 아는 기초 주제는 빼고, 남은 주제를 더 깊게 쓴다. index.md의 `수준` 열로 예전 노트를 어느 단계로 썼는지 볼 수 있다.
   - 주제 수에 제한은 없다. 수십 개여도 한 파일에 모두 넣는다. 다만 억지로 쪼개지 말고 "학생이 한 번에 공부할 단위"로 묶는다.
5. **노트 작성**: `$SKILL_DIR/templates/note.md` 구조를 그대로 따라 `suggested_file`에 쓴다. 폴더가 없으면 만든다.
   - frontmatter의 `covers`는 extract 출력의 `from ~ to`, `session`은 앞 8자
   - 설명 수준 표시: frontmatter `title`과 H1 끝에 ` · <level_label>`, `level`(숫자)과 `level_name`(이름), H1 바로 아래 인용문 첫 줄 `> 설명 수준: <level_label>. <level_audience>에게 맞춰 썼어요.`
   - 본문 전체를 수준 표의 '쓰는 방식'에 맞춘다. 용어를 어디까지 풀지, 비유를 쓸지, 코드 분량, 자가 점검 질문의 깊이가 단계마다 다르다
   - 목차 표를 먼저 채우고, `## N. 제목` 섹션을 순서대로 쓴다
   - 각 섹션은 제목 바로 아래에 `> 한 줄 요약: …`, 그다음 메타 줄을 정확히 이 형식으로 쓴다: `` `유형` 개념 | `태그` fastapi, alembic | `난이도` ★★☆ `` (index.md가 두 줄을 파싱한다)
   - 한 줄 요약은 index.md의 요약 열로 들어가 다음 실행의 중복 판단에 쓰인다. 제목을 되풀이하지 말고 **핵심 내용을 한 문장으로** 쓴다. 검색에 걸리도록 핵심 용어를 넣는다
   - 유형은 `개념` / `문제해결` / `도구·명령어` / `설계결정` / `워크플로` 중 하나
   - 해당 없는 소제목(예: 개념 유형의 "문제 → 원인 → 해결")은 생략해도 된다. 그 외 소제목은 모두 채운다
6. **등록**:
   ```bash
   $PY "$SKILL_DIR/scripts/study_notes.py" commit --agent $AGENT --session <extract 출력의 session> --file <쓴 노트 경로>
   ```
   체크포인트가 저장되고 `$HOME/StudyNotes/index.md`에 주제 행이 추가된다. 처음이면 `README.md`도 생긴다. 행의 `수준` 열에는 노트 frontmatter의 `level`이 들어간다.
7. **보고**: 노트의 절대 경로, 설명 수준, 주제 수, 주제 제목 목록을 사용자에게 3~6줄로 알린다. 노트 내용을 채팅에 다시 붙이지 않는다.
   처음 고른 실행이거나 기본값(2단계)으로 쓴 경우에는 "단계를 바꾸려면 `/study-notes 4`처럼 부르세요(Codex는 `$study-notes 4`)"를 한 줄 덧붙인다.

## 작성 규칙

- 한국어. 풀어야 할 용어(수준 표 기준)는 첫 등장 시 괄호로 한 줄 정의. 모든 설명에 "왜"를 포함한다.
- 순서: 상황 → 왜 필요한가(없으면 생기는 문제, 비유) → 핵심 개념(정의·원리) → 이 프로젝트에서 쓴 모습 → 흔한 실수 → 자가 점검 → 더 공부할 것
- 문제해결 유형은 **증상 → 원인 → 해결 → 재발 방지** 4단을 고정으로 쓴다. 오류 메시지는 원문 그대로 코드 블록에 넣는다.
- 코드·명령은 펜스 블록에 언어를 지정하고, 블록 위에 한 줄 설명을 쓴다. 옵션(`-I`, `--delete` 등)의 뜻을 풀이한다.
- 자가 점검 질문은 2~3개, 답을 바로 아래에 적는다. 질문 깊이는 수준에 맞춘다(1·2단계는 뜻과 이유, 3단계는 적용, 4·5단계는 설계 판단과 트레이드오프). 더 공부할 것은 키워드 2~3개와 "왜 다음에 배워야 하는지".
- 일반 md 편집기 호환: HTML 태그, Obsidian 전용 문법(`[[링크]]`, callout) 금지. 표는 GFM. 수식·이모지 남용 금지.
- 프로젝트 파일을 언급할 때는 저장소 기준 상대 경로를 백틱으로 쓴다.

## 문제가 생기면

- `세션 기록을 찾을 수 없습니다`: `--session`을 빼고 다시 실행한다.
- `이 폴더에서 연 Codex 스레드 기록이 없습니다`: Codex에서 다른 폴더를 열었거나 `--agent`가 틀렸다. `--cwd`에 Codex가 연 작업 폴더를 넣는다.
- 체크포인트를 되돌리고 싶으면 `$HOME/StudyNotes/.state/<세션id>.json`을 지운다. 그 세션은 처음부터 다시 정리된다.
- 상태 확인: `$PY "$SKILL_DIR/scripts/study_notes.py" status --agent $AGENT --cwd "$PWD"`
- 설명 수준 보기·바꾸기: `$PY "$SKILL_DIR/scripts/study_notes.py" level` / `... level 4`(또는 `level 실전`). 기억된 값은 `$HOME/StudyNotes/settings.json`에 있다.
- `알 수 없는 설명 수준입니다`: 1~5 숫자나 왕초보·입문·기초·실전·심화 중 하나로 다시 고른다.
