# 개념노트 정리 (study-notes)

Claude Code와 OpenAI Codex 어디서나 같은 방식으로 동작한다. Claude Code에서는 `/study-notes`, Codex에서는 `$study-notes`로 부른다.
`/study-notes 3`, `$study-notes 기초`처럼 설명 수준을 붙여 부르면 그 단계로 쓰고, 다음 실행을 위해 기억한다.

## 0. 호출 인자를 먼저 해석한다

스킬에 붙은 인자(`/study-notes <인자>`의 `<인자>`)로 할 일을 정한다. **인자 없음**, **단계**, **`u`**, **`c`**는 정리를 실행하고, 나머지는 안내·상태·취소만 하고 끝낸다. 대소문자는 구분하지 않는다. `u`만 단계와 함께 쓸 수 있고(`1 u`, `u 1` 모두 같다), 그 밖에는 인자가 여럿이면 첫 번째만 본다.

| 인자 | 할 일 |
|---|---|
| (없음) | 기억된 단계로 정리 실행 → "절차" |
| `1`~`5` 또는 `왕초보`·`입문`·`기초`·`실전`·`심화` | 그 단계로 정리 실행하고 단계를 기억 → "절차" |
| `u`, 또는 단계와 `u` | 대화에서 주제를 충분히 뽑아 목록을 만들고 에이전트로 쓴다 → "많이 쓰기 (u)" |
| `c`, `continue` | 목록에 남은 주제를 이어서 쓴다 → "이어 쓰기 (c)" |
| `h`, `help`, `?` | 아래 "사용법 (h)" 블록을 그대로 출력하고 끝. 정리하지 않는다 |
| `d`, `display`, `status` | 현재 단계와 정리 상태를 보여 주고 끝 → "상태 보기 (d)" |
| `s`, `stop`, `cancel` | 진행 중이던 정리를 취소하고 끝 → "취소 (s)" |
| 그 외 | `알 수 없는 옵션입니다: <인자>` 한 줄 뒤에 "사용법 (h)" 블록을 출력하고 끝. 정리하지 않는다 |

아래 명령의 `$PY`, `$SKILL_DIR`, `$AGENT`는 "준비" 절의 값이다.

### 사용법 (h)
아래 블록을 그대로 출력한다. Codex에서는 `/study-notes`를 `$study-notes`로 바꿔 출력한다.

```
study-notes — AI와의 개발 대화에 나온 개념을 교과서식 노트로 정리하는 스킬

사용법
  /study-notes          기억된 설명 수준으로, 지난 정리 이후의 대화를 살펴 정리
  /study-notes <단계>   그 단계로 정리하고 단계를 기억  (1 왕초보 · 2 입문 · 3 기초 · 4 실전 · 5 심화)
  /study-notes u        대화에서 주제를 충분히 뽑아 많이 쓰기 (한 번에 30개까지, /study-notes 1 u 처럼 단계도 지정)
  /study-notes c        목록에 남은 주제를 이어서 쓰기 (continue) — 토큰이 끊긴 뒤에도 된다
  /study-notes d        현재 설명 수준과 정리 상태 보기 (display)
  /study-notes s        진행 중인 정리 취소 (stop) — 먼저 ESC로 멈춘 뒤 입력
  /study-notes h        이 사용법 (help)

예
  /study-notes 3        3단계 기초로 정리
  /study-notes 실전     4단계 실전으로 정리

메모
  · 대화에 나온 개념 중 그 단계의 개념사전 항목을 골라 한 번에 주제 3~5개를 쓴다 (u는 최대 30개)
  · 한 번 쓴 개념은 다시 쓰지 않는다. 노트는 ~/StudyNotes/AX개념노트/ 에 쌓인다
  · 사전은 아직 백엔드·API 중심이다. 사전에 없는 개념은 후보함에 적어 둔다
  · s로 취소해도 체크포인트는 그대로라서, 다음 실행 때 같은 대화부터 다시 살핀다
```

### 상태 보기 (d)
```bash
$PY "$SKILL_DIR/scripts/study_notes.py" status --agent $AGENT --cwd "$PWD" --session <세션id>
```
(세션 id는 "절차" 1번과 같은 방법으로 찾고, Codex면 `--session`을 뺀다.) 출력 JSON을 아래 모양의 표로 보여 주고 끝낸다. JSON 원문은 붙이지 않는다.

| 항목 | 값 |
|---|---|
| 설명 수준 | `level_label` (`level_source`가 `saved`면 "저장됨", `unset`이면 "기본값·아직 안 고름") |
| 프로젝트 / 세션 | `project` / `session` 앞 8자 |
| 이 세션 정리 횟수 | `run_count`회, 마지막 정리 `last_summarized_at` |
| 미정리 메시지 | `unsummarized_messages`개 |
| 개념사전 / 쓴 개념 | 버전 `catalog_version` / `concepts_used`개 |
| 주제 목록 | `queue`의 전체 `total`개: 남음 `pending`, 등록 대기 `written`, 끝남 `done` (남았으면 `/study-notes c`) |
| 진행 중인 정리 | `in_progress`가 null이면 "없음", 있으면 노트 경로와 `started_at` (ESC 뒤 `/study-notes s`로 취소 가능) |
| 이 세션의 노트 | `files`의 파일 이름만 쉼표로 잇는다. 표 칸에 `<br>`을 쓰지 않는다 |

표 아래에 한 줄: "단계를 바꾸려면 `/study-notes 1`~`5`, 정리를 시작하려면 `/study-notes`".

### 취소 (s)
정리 도중 사용자가 ESC로 실행을 끊은 뒤 부르는 옵션이다. 다른 레벨로 시작된 것을 알았거나 급한 일이 생겨 정리를 포기할 때 쓴다.
```bash
$PY "$SKILL_DIR/scripts/study_notes.py" cancel --agent $AGENT --cwd "$PWD" --session <세션id>
```
스크립트가 extract는 했지만 commit은 안 한 정리를 찾아 **미완성 노트 파일과 델타 파일을 지우고**, 체크포인트는 그대로 둔다(이미 등록된 노트는 건드리지 않는다). 출력의 `message`를 그대로 전하고, `removed_note`가 있으면 지운 파일 경로를 한 줄 덧붙인다. `cancelled`가 false면 "진행 중인 정리가 없습니다"만 알린다. 이 뒤로는 정리 작업을 이어 가지 않는다. 주제 목록과 완료한 주제는 지우지 않으므로 `/study-notes c`로 이어 쓸 수 있다고 덧붙인다.

### 정리 시작 배너
정리를 실행할 때는 "절차" 3번 extract가 끝난 직후, 델타를 읽기 전에 아래 한 줄을 먼저 출력하고 **기다리지 않고 바로 진행**한다. 사용자가 지금 단계가 아니라고 판단하면 ESC로 멈추고 `/study-notes s`로 취소할 수 있게 하기 위한 안내다.

```
📒 study-notes · 설명 수준 <level_label> (<출처>) · 단계 바꾸기 /study-notes 1~5 · 상태 /study-notes d · 취소 ESC 후 /study-notes s
```
`<출처>`는 `level_source`가 `argument`면 "이번에 지정", `saved`면 "저장된 값", 그 외면 "기본값". Codex에서는 `$study-notes`로 바꿔 쓴다.

## 가장 중요한 원칙: 대화의 정리가 아니라 교과서

- **대화는 무엇을 쓸지 고르는 계기일 뿐이다.** 노트는 대화 내용을 옮기거나 요약하지 않는다. 그 개념을 교과서처럼 처음부터 설명한다.
- **그때의 상황을 몰라도 읽혀야 한다.** 일주일 뒤에 읽는 사람은 그 대화를 잊었다. 특정 프로젝트의 파일, 함수, 오류, 결정을 본문에 쓰지 않는다. 예제도 누구나 따라 할 수 있는 일반 예제로 새로 만든다.
- **주제와 제목은 사전이 정한다.** 대화에서 주제를 지어내지 않는다. 이름은 사전의 제목을 그대로 쓴다.
- 쓰고 나서 스스로 확인한다: "일주일 뒤에 다시 읽고 싶은 노트인가? 이 노트만 읽은 그 단계의 학생이 학습 목표대로 할 수 있는가?" 아니면 더 고친다.

## 설명 수준 (5단계)

배움일기 코치 앱의 '답변 수준'과 같은 다섯 단계다. 단계 이름·대상·방식의 기준은 스크립트의 `LEVELS`다. 고르기 전 기본값은 2단계다.

| 단계 | 독자 | 배우고 나면 | 쓰는 방식 |
|---|---|---|---|
| 1단계 왕초보 | 컴퓨터·IT 용어가 낯선 분 | 비유로 설명할 수 있다 | 중학생도 아는 쉬운 말과 존댓말. 일상 비유로 큰 그림을 먼저 보여 주고, 용어는 나오자마자 푼다. 코드는 꼭 필요할 때만 아주 짧게 |
| 2단계 입문 | 비전공으로 막 입과한 분 | 보고 따라 만들 수 있다 | 쉬운 말과 존댓말로 쓰되 핵심 용어는 알려 주고 처음 나올 때 한 줄로 푼다. 짧은 예시 코드와 주석, 왜 필요한지, 흔한 실수 |
| 3단계 기초 | 변수·함수·조건문을 익힌 분 | 배운 것을 변형해 혼자 기능을 구현할 수 있다 | 존댓말. 아는 용어는 그대로 쓰고 새 개념만 푼다. 작은 단계로 나눈 예제, 그렇게 되는 이유, 자주 하는 실수와 해결 방법 |
| 4단계 실전 | 웹 프로젝트를 만드는 분 | 설계를 골라 근거를 말하고 오류 원인을 찾을 수 있다 | '~다'체. 기본 용어는 풀지 않는다. 동작 원리, 설계 선택과 손익, 재현한 오류와 진단 순서 |
| 5단계 심화 | 전공자·실무 경험자 | 내부 동작과 손익을 근거로 판단하고 장애를 분석할 수 있다 | '~다'체. 기초 설명 생략. 내부 구현, 성능·보안·확장성의 손익, 근거가 되는 공식 문서·표준, 대안 설계 비교 |

노트에는 수준을 이렇게 표시한다(템플릿 참고): frontmatter `title` 끝의 ` · 3단계 기초`와 `level: 3`·`level_name: 기초`, H1 제목 끝의 ` · 3단계 기초`, H1 바로 아래 인용문 첫 줄 `> 설명 수준: 3단계 기초. 변수·함수·조건문을 익힌 분에게 맞춰 썼어요.`
H1과 인용문 사이에는 다른 문단을 넣지 않는다. 노트를 올리는 학습 관리 앱이 H1 바로 뒤의 인용문을 노트 요약으로 읽는다.

## 준비: 세 변수를 먼저 정한다

아래 명령의 `$PY`, `$SKILL_DIR`, `$AGENT`는 실행 전 실제 값으로 바꾼다.

- `$PY` = 파이썬 실행 명령. macOS/Linux는 `python3 -I`, Windows는 `python -I` (없으면 `py -3 -I`). 3.10 이상. 셸 변수에 담지 말고 값을 명령에 그대로 쓴다. zsh는 변수 안의 띄어쓰기를 나누지 않아 `PY="python3 -I"; $PY ...`가 실패한다.
- `$SKILL_DIR` = **이 SKILL.md가 들어 있는 폴더**. 홈 디렉터리는 `~` 대신 `$HOME`으로 쓴다 (bash와 PowerShell 모두에서 풀리고, PowerShell은 외부 프로그램 인자의 `~`를 풀지 않는다).
  - Claude Code 플러그인: `${CLAUDE_PLUGIN_ROOT}/skills/study-notes`
  - Claude Code 직접 복사: `$HOME/.claude/skills/study-notes`
  - Codex: `$HOME/.codex/skills/study-notes` (`CODEX_HOME`을 바꿨다면 `$CODEX_HOME/skills/study-notes`)
- `$AGENT` = 지금 실행 중인 도구. Claude Code면 `claude`, Codex면 `codex`. 스크립트가 이 값으로 어느 쪽 대화 기록을 읽을지 정한다.

Windows 주의: 명령은 Git Bash 또는 PowerShell에서 실행한다 (cmd.exe는 `$HOME`, `$PWD`를 모른다). 경로 구분자는 `/`를 써도 된다.
Git Bash의 `$PWD`가 `/c/Users/...` 형태여도 스크립트가 `C:\Users\...`로 바꿔 처리한다. 노트는 `%USERPROFILE%\StudyNotes`에 생긴다.

Codex 주의: 노트 폴더 `$HOME/StudyNotes`는 작업 폴더 밖이다. 노트를 쓰거나 `commit`을 실행할 때 샌드박스가 막으면 쓰기 승인(escalation)을 요청한다. 기록 읽기(`~/.codex/sessions`, `~/.codex/state_*.sqlite`)는 읽기 전용이다.

## 절차

1. **세션 id 확인**
   - Claude Code: 시스템 프롬프트의 Scratchpad directory 경로 마지막 디렉터리명이 현재 세션 id다 (예: `b4a801d7-…`). 찾을 수 없으면 `--session`을 생략한다.
   - Codex: 스레드 id가 프롬프트에 없으므로 `--session`을 **생략**한다. 스크립트가 스레드 목록 DB에서 "이 작업 폴더에서 사용자가 연 가장 최근 스레드"를 고른다. 이후 `commit`에는 extract 출력의 `session` 값을 그대로 넘긴다.
2. **설명 수준 정하기**
   - 사용자가 부르면서 단계를 말했으면(`/study-notes 3`, `$study-notes 기초`, "4단계로 정리해 줘" 등) 그 값을 3번 증분 추출의 `--level`로 넘긴다. 넘긴 값은 다음 실행을 위해 기억된다.
   - 말하지 않았으면 기억된 단계를 본다:
     ```bash
     $PY "$SKILL_DIR/scripts/study_notes.py" level
     ```
     `level_source`가 `saved`면 그 단계로 쓴다(`--level`은 생략).
   - `unset`이면 처음 실행이다. 출력의 `levels`로 다섯 단계 표(단계·대상·방식)를 보여 주고 "번호(1~5)로 골라 주세요. 고르기 전에는 2단계 입문으로 씁니다."라고 물은 뒤 **멈추고 답을 기다린다**. 보기가 다섯 개라 선택지 도구(보기 최대 4개)는 쓰지 않고 채팅으로 묻는다. 답을 받으면 그 값을 `--level`로 넘긴다.
   - 사용자에게 물을 수 없는 실행(예약 실행 등)이면 2단계로 쓰고, 보고할 때 바꾸는 방법을 알린다.
3. **증분 추출과 후보 찾기**:
   ```bash
   $PY "$SKILL_DIR/scripts/study_notes.py" extract --agent $AGENT --cwd "$PWD" --session <세션id> [--level <단계>]
   ```
   `new_messages`가 0이면 "정리할 새 대화가 없습니다"라고 알리고 끝낸다. 단계 값이 틀리면 스크립트가 고를 수 있는 값을 알려 주고 멈춘다.
   그 밖에는 "정리 시작 배너"(0절) 한 줄을 출력한 뒤 진행한다. 출력에서 쓰는 값은 다음과 같다.
   - `candidates`: 대화에 이름이 나왔고 이 단계이며 아직 안 쓴 사전 항목. 중요도 순이다. `candidate_total`이 전체 수다.
   - `other_levels`: 다른 단계에 있는 후보 수 (`{"3": 2}`면 3단계에 2개).
   - `delta_path`: 대화 파일. `suggested_file`: 이번에 쓸 노트 경로. `note_no`: 노트 번호. `catalog_version`: 사전 버전.
   - `level_label`·`level_audience`: 이번 노트의 설명 수준.
4. **주제 고르기**:
   - `candidates`에서 **최대 5개, 되도록 3개 이상** 고른다. 후보 밖에서 고르지 않는다. 억지로 채우지 않는다. 두 개뿐이면 두 개만 쓴다.
   - 스크립트는 이름이 나왔는지만 본다. 대화에서 그 개념을 **실제로 다뤘는지** `delta_path`를 확인해 거른다. 파일 이름, 변수 이름, 도구 출력에만 스친 것은 뺀다. `matched`의 낱말로 검색하면 빠르다.
     `grep -n -i -E "jwt|토큰" "<delta_path>" | head -20` (PowerShell은 `Select-String -Path "<delta_path>" -Pattern "jwt|토큰" | Select-Object -First 20`)
   - 남은 것 중에서 중요도가 높은 것을 먼저 고르고, 중요도가 같으면 대화에서 많이 다룬 것을 고른다.
   - **사전에 없는 개념을 적어 둔다**: 대화에서 실제로 다뤘는데 후보에 없고 공부할 가치가 있는 개념이 눈에 띄면 이름을 적는다. 델타가 길면 사용자 메시지(`### 사용자`) 위주로 훑으면 된다. 프로젝트 전용 이름이나 비밀값은 적지 않는다.
     ```bash
     $PY "$SKILL_DIR/scripts/study_notes.py" candidate --cwd "$PWD" --title "개념 이름" [--title "다른 이름"]
     ```
   - **고를 주제가 하나도 없으면** 노트를 만들지 않는다. `cancel`을 실행해 진행 중 표시를 지운 뒤(체크포인트는 그대로라 사전이 늘면 이 대화를 다시 살필 수 있다) 이렇게 알리고 끝낸다: "이번 대화에 나온 개념 중 <level_label> 사전 항목이 없어 노트를 만들지 않았습니다. 사전은 아직 백엔드·API 중심입니다. 사전 저장소에서 `/dic-maker`로 늘릴 수 있습니다." `other_levels`가 있으면 "<N>단계에는 <M>개가 있습니다. `/study-notes <N>`으로 부를 수 있습니다."를, 후보함에 적은 것이 있으면 그 이름을 덧붙인다.
5. **사전 내용 가져오기**:
   ```bash
   $PY "$SKILL_DIR/scripts/study_notes.py" concept <id> [<id> ...]
   ```
   항목마다 `title`, `en`, `summary`, `objectives`(학습 목표), `prerequisites`(선수 개념), `related`(헷갈리는 개념), `terms`(이 주제에서 함께 풀 용어), `refs`(공식 문서), `importance`가 나온다.
6. **노트 작성**: `$SKILL_DIR/templates/concept-note.md` 구조를 그대로 따라 `suggested_file`에 쓴다. 폴더가 없으면 만든다. 아래 "작성 규칙"을 지킨다.
   - 쓰기 직전에 같은 경로의 파일이 있으면 다른 세션이 만든 노트다. 덮어쓰지 말고 파일명 끝 번호를 올린다.
   - 값 채우기: `<level_label>`, `<level_name>`, `<level_audience>`는 extract 출력, `#NN`은 `note_no`를 두 자리로, `catalog_version`은 extract 출력, `topics`는 주제 수. `level`은 숫자 하나만 쓴다.
   - 주제는 `## 1. <사전의 title> (<사전의 en>)`처럼 번호를 붙이고 중요도 순으로 놓는다.
   - 메타 줄은 정확히 이 모양이다: `` `유형` 개념 | `태그` jwt, 인증 | `난이도` ★★★ | `개념` be.auth.jwt-flow | `단계` 3단계 기초 | `중요도` ★★★ ``. `유형`은 항상 `개념`, `난이도`의 별 수는 단계 숫자, `중요도`는 사전의 값, 태그는 소문자로 쉼표로 나눈다.
7. **등록**:
   ```bash
   $PY "$SKILL_DIR/scripts/study_notes.py" commit --agent $AGENT --session <extract 출력의 session> --file <쓴 노트 경로>
   ```
   등록 전에 노트를 검사한다. 통과하지 못하면 오류 목록을 보여 주고 등록하지 않으며, 체크포인트도 그대로다. **오류를 고쳐 같은 명령을 다시 실행한다.** 통과할 때까지 반복하고, 검사를 피하려고 내용을 지우지 않는다.
   통과하면 체크포인트가 저장되고 `$HOME/StudyNotes/index.md`에 주제 행이 추가되며, 쓴 개념은 `concepts_used.json`에 남아 다시 후보로 나오지 않는다.
8. **보고**: 노트의 절대 경로, 설명 수준, 주제 제목 목록, 예제를 실행해 확인했는지(못 한 것은 무엇인지)를 3~7줄로 알린다. 후보함에 적은 개념이 있으면 이름을 덧붙인다. 노트 내용을 채팅에 다시 붙이지 않는다.
   처음 고른 실행이거나 기본값(2단계)으로 쓴 경우에는 "단계를 바꾸려면 `/study-notes 4`처럼 부르세요(Codex는 `$study-notes 4`)"를 한 줄 덧붙인다.

## 많이 쓰기 (u)

대화에서 주제를 충분히 뽑아 목록을 만든 뒤, 주제마다 에이전트 하나가 쓴다. 범위는 현재 세션의 마지막 노트 이후부터 지금까지의 대화다. 일반 실행과 달리 3~5개로 줄이지 않는다.

스크립트 출력은 `head`로 자르지 않는다. 잘리면 주제가 빠진다. 사용 한도나 비용을 짐작해 주제 수나 분량을 줄이지 않는다. 한도 오류가 실제로 났을 때만 멈추고, 그때는 오류를 그대로 알린다.

1. "절차" 1·2번대로 세션 id와 설명 수준을 정한다. `1 u`처럼 단계를 말했으면 `--level`로 넘긴다.
2. 후보를 모두 받는다:
   ```bash
   $PY "$SKILL_DIR/scripts/study_notes.py" extract --agent $AGENT --cwd "$PWD" --session <세션id> --all [--level <단계>]
   ```
   `new_messages`가 0이면 "정리할 새 대화가 없습니다"라고 알린다. 목록에 남은 주제가 있으면 `/study-notes c`를 안내하고 끝낸다. 그 밖에는 "정리 시작 배너"(0절)를 출력한다.
3. **후보를 거른다.** 빠뜨리는 쪽보다 충분히 뽑는 쪽을 택하되, 대화에서 실제로 다루지 않은 것은 뺀다. `matched`의 낱말이 파일 이름, 변수 이름, 다른 뜻으로만 쓰였으면 뺀다. 후보가 많으면 하나의 명령으로 한꺼번에 센다.
   ```bash
   grep -c -i -E "jwt" "<delta_path>"
   ```
   후보에 없는 개념은 "절차" 4번처럼 후보함에 적는다. 남은 주제가 하나도 없으면 "절차" 4번의 "고를 주제가 하나도 없으면"을 따른다.
4. 목록에 넣는다. 이미 쓴 개념과 이미 목록에 있는 주제는 스크립트가 건너뛴다.
   ```bash
   $PY "$SKILL_DIR/scripts/study_notes.py" queue-add --session <extract 출력의 session> --ids <id> <id> ...
   ```
5. 목록의 주제 수와 제목을 한 번 보여 주고 **기다리지 않고** "이어 쓰기 (c)"로 넘어간다. 목록이 30개를 넘으면 이번에는 30개까지 쓰고 나머지는 `c`로 쓴다고 알린다.

## 이어 쓰기 (c)

목록에서 아직 쓰지 않은 주제를 쓴다. 토큰이 끊긴 뒤 새 세션에서 불러도 된다. 세션 id가 필요 없다.

1. 이번에 쓸 주제를 받는다. 한 번에 최대 30개이고 중요도 순이다:
   ```bash
   $PY "$SKILL_DIR/scripts/study_notes.py" queue-next
   ```
   `topics`가 비어 있고 `queue.written`도 0이면 "이어 쓸 주제가 없습니다"라고 알리고 끝낸다. `topics`만 비어 있으면 3번으로 간다.
2. **주제마다 에이전트 하나**로 쓴다. 주제가 한두 개뿐이어도 직접 쓰지 말고 에이전트로 쓴다. 출력의 `agent_concurrency`(5개)까지 동시에 돌리고, 하나가 끝나면 다음 주제를 시작한다. 모델은 지정하지 않아 지금 쓰는 모델을 따른다. 에이전트를 띄울 수 없는 환경(Codex 등)에서는 같은 일을 순서대로 직접 한다. 에이전트에게 아래를 그대로 전하고, 줄이거나 분량 제한을 덧붙이지 않는다. `<level_label>` 같은 값은 출력의 `levels`에서 주제의 `level`로 찾는다.
   ```
   당신은 한국어 교재 집필자입니다. 주제 하나를 교과서식으로 씁니다. 대화를 알 필요가 없고 쓰지도 않습니다.
   - 주제 id: <id>, 설명 수준: <level_label> (<level_audience>), 쓰는 방식: <level_style>
   - 먼저 읽을 것: <PY> "<SKILL_DIR>/scripts/study_notes.py" guide 의 출력 전부. 작성 규칙과 노트 틀이 나옵니다. SKILL.md를 따로 읽거나 sed로 자르지 않습니다. 명령 사이에 `echo ====`를 넣지 않습니다. zsh에서 오류가 납니다.
   - 사전 내용: <PY> "<SKILL_DIR>/scripts/study_notes.py" concept <id>
   - 쓸 파일: <draft_file>. "## 1. <사전의 title> (<사전의 en>)" 줄로 시작하는 주제 하나만 씁니다. frontmatter, H1, 목차는 쓰지 않습니다.
   - 예제 실행: 임시 폴더 <TMP>/study-notes/<id> 안에서만 합니다. 포트는 <9000 + 슬롯 번호 × 10>부터 10개만 씁니다. 서버는 `명령 > log.txt 2>&1 & SERVER=$!`로 띄우고 `kill "$SERVER"; wait "$SERVER" 2>/dev/null`로 내린 뒤, 그 포트에 다시 요청해 연결이 안 되는 것을 확인합니다. `kill %1`은 쓰지 않습니다. 다른 파일과 프로세스는 건드리지 않습니다. git을 쓰지 않고 다른 스킬을 부르지 않습니다. .env를 읽지 않습니다.
   - 다 쓰면 검사합니다: <PY> "<SKILL_DIR>/scripts/study_notes.py" queue-done --id <id>
     통과할 때까지 고칩니다. 검사를 피하려고 내용을 지우지 않습니다.
   - 명령 하나가 권한 거부로 막혀도 Bash 전체가 막힌 것이 아닙니다. 더 단순한 명령이나 다른 도구로 바꿔 계속합니다. 세 번 바꿔 시도해도 안 될 때만 실패로 보고합니다.
   - 마지막 응답은 두 줄입니다. 첫 줄은 "완료 <id>" 또는 "실패 <id>: 이유", 둘째 줄은 실행하지 못한 것(없으면 "없음")입니다.
   ```
   `<TMP>`는 임시 폴더(작업 공간의 scratchpad, 없으면 시스템 임시 폴더)이고, 슬롯 번호는 동시에 도는 에이전트마다 다르게 준다.

   에이전트가 실패해도 멈추지 않는다. 사용자에게 어떻게 할지 묻지 말고 남은 주제를 계속 띄운다. 목록이 끝나면 실패한 주제만 한 번 더 에이전트로 쓴다. 그래도 실패하면 목록에 남겨 두고 3번으로 간다.
3. 끝나면 묶어서 등록한다. 실패한 주제가 있어도 실행한다. 실패한 주제는 목록에 남아 다음 `c`에서 다시 쓴다:
   ```bash
   $PY "$SKILL_DIR/scripts/study_notes.py" queue-bundle
   ```
   단계별로 20개씩 한 파일이 되고, 파일마다 검사를 거쳐 `index.md`에 오른다. 이때 살펴본 대화의 체크포인트도 옮겨진다.
4. **남은 서버 정리**: 에이전트가 내리지 못한 예제 서버가 있으면 이번 실행의 임시 폴더에서 돌던 것만 내린다. 다른 프로그램은 건드리지 않는다. macOS/Linux:
   ```bash
   for p in $(lsof -nP -iTCP:9000-9099 -sTCP:LISTEN -t 2>/dev/null); do lsof -a -p "$p" -d cwd -Fn | grep -qF "<TMP>/study-notes/" && kill "$p"; done
   ```
5. **보고**: 노트의 절대 경로와 파일별 주제 수, 실패한 주제, 실행하지 못한 것을 알린다. `queue.pending`이 남았으면 "남은 주제 N개는 `/study-notes c`로 이어 쓸 수 있습니다"를 덧붙인다.

토큰이 끊기면 그대로 멈춘다. 검사를 통과한 주제는 파일로 남아 있으니 다음에 `/study-notes c`를 부르면 잃는 것은 쓰던 주제뿐이다. 묶기 전에 끊겼어도 다음 `c`가 함께 묶는다.

## 작성 규칙

- **소제목은 템플릿의 순서 그대로** 모두 쓴다: 학습 목표, 먼저 알아야 할 것, 왜 필요한가, 핵심 개념, 예제로 이해하기, 비슷한 개념과 차이, 흔한 실수, 직접 해 보기, 확인 문제, 정답, 공식 문서.
- **학습 목표**는 사전의 `objectives`를 글자 그대로 옮긴다. 노트 전체가 이 목표를 이루게 쓴다.
- **먼저 알아야 할 것**에는 `prerequisites`를 이름과 한 줄 뜻으로 적는다. 이 노트만 읽어도 따라올 수 있게 한다.
- **용어**: `terms`는 본문에서 뜻을 풀어 준다. **비슷한 개념과 차이**에는 `related`를 활용한다.
- **사실 확인**: `refs`의 공식 문서를 근거로 쓴다. 읽을 수 있으면 읽고 확인한다. 기억만으로 값이나 동작을 단정하지 않는다. 틀리기 쉬운 값(기본값, 버전, 모델 이름, 종료일)은 특히 확인하고, 빨리 바뀌는 것은 확인한 버전이나 날짜를 적는다.
- **예제는 실제로 실행한다.** 코드와 명령은 임시 폴더에서 돌려 보고 나온 출력을 그대로 적는다. 프로젝트 폴더에 파일을 만들지 않는다. **출력을 지어내지 않는다.** 환경이나 키가 없어 실행하지 못한 것은 본문에 못 했다고 적고 보고에도 알린다. 윈도우 명령을 맥에서 썼다면 실행하지 못했다고 밝힌다.
- **명령은 코드 블록에 쓴다.** 문장 속 인라인 코드에는 명령 이름만 쓰고(`curl`), 옵션까지 쓴 명령은 언어를 지정한 코드 블록(` ```bash `)으로 옮긴다. 학습장 앱 앞단이 백틱·`|`·`;` 바로 뒤나 작은따옴표로 끝난 줄의 바로 다음 줄에 오는 `curl`, `wget`, `python -c`, `python -m`, `perl -e`를 명령 주입으로 보고 업로드를 막는다. JSON을 보내는 `curl`을 여러 줄 쓸 때는 `req() { curl -s "$@"; }`처럼 함수로 묶고, 파이썬 모듈은 `python3 -m`으로 쓴다. `commit` 검사가 알려진 표기를 잡지만 전부는 아니다.
- **실행 환경은 주제 안에 쓴다.** 패키지 버전과 실행 환경은 그 주제의 "예제로 이해하기"나 "공식 문서"에 적는다. 목차에는 표만 둔다. 앱은 목차를 버리므로 그 아래 글은 사라진다. "이 실행에서는"처럼 노트를 쓰던 때를 가리키는 말도 쓰지 않는다.
- **수치는 조건과 함께 적는다.** 잰 값은 환경을 밝히고 "이 데이터에서"로 한정한다. 한 번의 측정을 일반 법칙처럼 쓰지 않는다.
- **예제는 한국어로 쓴다.** 독자는 한국인이다. 코드 안의 문구, 표본 데이터, 메시지를 한국어로 쓴다. 영어 출력은 있는 그대로 옮긴다.
- **비밀값을 쓰지 않는다.** `.env` 내용, 토큰, 키, 이메일, 내부 주소는 예제에도 넣지 않는다.
- **확인 문제**는 2개 이상, 단계의 목표를 확인하는 질문으로 쓴다. 번호 목록(`1. `)으로 쓰고 **정답**에 같은 수의 번호로 답과 이유를 쓴다. 정답은 문제 바로 아래가 아니라 "정답" 소제목에 모은다. 노트만 읽고 풀 수 있어야 한다.
- **공식 문서**에는 `refs`를 링크로 적고 무엇을 볼 수 있는지 한 줄을 덧붙인다.
- **분량**: 주제 하나에 A4 1~2쪽. 최소 분량 미만이면 검사에 걸리지만, 길게 늘이지 않는다. 표와 코드는 이해에 필요한 만큼만 쓴다.
- **쓰지 않는 표현**: 이번 대화, 이 프로젝트, 우리 앱, 앞서 말한 같은 표현과 프로젝트 파일 경로는 본문에 쓰지 않는다(코드 블록 밖 기준으로 검사한다).
- **만난 곳**은 선택이다. 쓰더라도 공식 문서 뒤에 "2026-11-03 스트리밍 채팅을 만들다 만났다"처럼 한 줄만 쓴다.
- 일반 md 편집기 호환: HTML 태그, Obsidian 전용 문법(`[[링크]]`, callout) 금지. 표는 GFM. 수식·이모지 남용 금지. 코드는 펜스 블록에 언어를 지정한다.

## 문제가 생기면

- `세션 기록을 찾을 수 없습니다`: `--session`을 빼고 다시 실행한다.
- `이 폴더에서 연 Codex 스레드 기록이 없습니다`: Codex에서 다른 폴더를 열었거나 `--agent`가 틀렸다. `--cwd`에 Codex가 연 작업 폴더를 넣는다.
- `노트 검사를 통과하지 못해`: 목록대로 고쳐 다시 commit 한다. `학습 목표가 빠졌다`면 사전의 문장을 글자 그대로 넣는다.
- `개념사전을 읽을 수 없습니다`: 스킬 폴더의 `catalog.json`이 없다. 스킬을 다시 설치한다.
- 어떤 개념을 다시 쓰고 싶으면 `$HOME/StudyNotes/concepts_used.json`에서 그 항목을 지운다.
- 체크포인트를 되돌리고 싶으면 `$HOME/StudyNotes/.state/<세션id>.json`을 지운다. 그 세션은 처음부터 다시 살핀다.
- 상태 확인: `/study-notes d` (= `$PY "$SKILL_DIR/scripts/study_notes.py" status --agent $AGENT --cwd "$PWD"`)
- 정리를 중간에 그만두고 싶으면: ESC로 멈춘 뒤 `/study-notes s` (= `... cancel ...`). 미완성 노트가 지워지고 체크포인트는 남는다.
- 설명 수준 보기·바꾸기: `$PY "$SKILL_DIR/scripts/study_notes.py" level` / `... level 4`(또는 `level 실전`). 기억된 값은 `$HOME/StudyNotes/settings.json`에 있다.
- `알 수 없는 설명 수준입니다`: 1~5 숫자나 왕초보·입문·기초·실전·심화 중 하나로 다시 고른다.
- 노트 폴더를 바꾸려면 환경 변수 `STUDY_NOTES_ROOT`를 쓴다. 시험할 때 실제 노트와 섞이지 않게 하는 데 쓸 수 있다.
- `주제 검사를 통과하지 못했습니다`: 쓴 파일을 고쳐 `queue-done`을 다시 실행한다.
- 주제 목록에서 어떤 주제를 빼고 싶으면 `$HOME/StudyNotes/topic_queue.json`에서 그 항목을 지운다. 완료한 주제는 `$HOME/StudyNotes/.parts/`에 등록 전까지 있다.
