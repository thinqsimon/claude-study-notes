# AX 풀스택 개념사전

AX(AI 전환) 서비스를 만드는 풀스택 개발자가 공부할 개념을 **5단계·11분야·중요도**로 정리한 목록이다.
`/study-notes` 스킬은 이 사전을 기준으로 노트 주제를 고르고, 한 번 쓴 항목은 다시 쓰지 않는다.

특정 교육과정의 진도를 따르지 않는다. 풀스택과 AX 실무에 필요한 지식을 **중요한 순서로** 늘어놓는다.

단계별 사전은 [dist/](dist/README.md)에 있다.

## 폴더

```text
catalog/
  VERSION          사전 버전
  CHANGELOG.md     버전별 변경
  domains.json     분야 11개
  levels.json      5단계 기준과 항목 수 목표
  sources.md       범위를 대조한 기준 자료
  items/<분야>.json 항목 원본 (여기만 고친다)
  dist/            단계별 사전과 catalog.json (자동 생성, 직접 고치지 않는다)
  tools/catalog.py 검사·생성 도구 (표준 라이브러리만 쓴다)
```

```bash
python3 -I catalog/tools/catalog.py format   # 항목 파일 모양 맞추기
python3 -I catalog/tools/catalog.py check    # 규칙 검사
python3 -I catalog/tools/catalog.py build    # dist 다시 만들기
python3 -I catalog/tools/catalog.py stats    # 단계·분야별 현황
python3 -I catalog/tools/catalog.py links    # 링크 확인 (네트워크 사용)
python3 -I catalog/tools/catalog.py lint-note <노트.md>  # 개념노트 규칙 검사
```

## 항목 형식

```json
{
  "id": "be.http.methods-status",
  "title": "HTTP 메서드와 상태 코드",
  "en": "HTTP Methods and Status Codes",
  "kind": "topic",
  "level": 2,
  "importance": 1,
  "group": "HTTP",
  "summary": "GET·POST로 할 일을 말하고 200·404·500으로 결과를 듣는 HTTP의 기본 약속이다.",
  "objectives": ["2xx·4xx·5xx가 각각 어느 쪽 문제인지 구분할 수 있다"],
  "prerequisites": ["be.http.web-conversation"],
  "aliases": ["상태 코드", "status code", "404"],
  "refs": ["https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status"]
}
```

| 필드 | 뜻 | 규칙 |
|---|---|---|
| `id` | 바뀌지 않는 이름표. 중복을 막는 기준이다 | `<분야>.<묶음>.<이름>`. 한 번 정하면 바꾸지 않는다 |
| `title`, `en` | 교과서 목차에 들어갈 이름 | 문장이나 사건 이야기가 아니라 개념의 이름으로 쓴다 |
| `kind` | `topic` 주제(노트 1~2쪽), `term` 용어(노트 반쪽) | |
| `level` | 처음 배우는 단계 1~5 | 아래 단계 기준 |
| `importance` | 1 필수, 2 중요, 3 선택 | 아래 중요도 기준 |
| `group` | 분야 안의 묶음 | |
| `summary` | 그 단계 눈높이의 한 문장 | 직접 쓴다. 자료의 문장을 옮기지 않는다 |
| `objectives` | 노트가 가르칠 목표 2~4개 (주제만) | "~할 수 있다"로 끝난다 |
| `prerequisites` | 먼저 알아야 할 항목 | 같거나 낮은 단계만. 순환 금지 |
| `parent` | 이 용어를 가르치는 주제 (용어만) | 그 주제의 노트가 있으면 용어도 다룬 것으로 본다 |
| `related` | 비슷해서 헷갈리는 항목 | 노트의 "비슷한 개념과 차이"에 쓴다 |
| `aliases` | 대화에서 이 항목을 찾을 때 쓰는 말 | 한글·영어를 함께, 2자 이상 |
| `refs` | 공식 자료 링크 | 2단계 이상 주제는 필수 |
| `volatile`, `checked_at` | 빠르게 바뀌는 내용과 확인 날짜 | 모델명·가격·법규 등 |
| `replaced_by` | 없앤 항목을 대신하는 id | 항목을 지우지 않고 이 값을 단다 |

같은 분야도 단계마다 **별도 항목**이다. 항목이 다르면 가르칠 내용이 다르기 때문이다.

| 단계 | HTTP | 임베딩 |
|---|---|---|
| 1 | 브라우저와 서버의 대화: 요청과 응답 | 임베딩: 글의 뜻을 숫자로 바꾸기 |
| 2 | HTTP 메서드와 상태 코드 | 코사인 유사도로 비슷한 문장 찾기 |
| 3 | HTTP 헤더와 본문 | 벡터 DB로 문서 검색 만들기 |
| 4 | CORS: 출처가 다른 요청을 허용하는 규칙 | RAG 검색 품질 개선 |
| 5 | HTTP/1.1·HTTP/2·HTTP/3의 연결과 성능 | 벡터 인덱스의 내부: HNSW와 IVF |

## 단계 기준

| 단계 | 대상 | 배우고 나면 | 넣는 것 | 넣지 않는 것 |
|---|---|---|---|---|
| 1 왕초보 | 컴퓨터·IT 용어가 낯선 분 | 비유로 설명할 수 있다 | 큰 그림, 일상 비유로 풀 수 있는 개념, 도구 설치와 첫 실행, 용어의 뜻 | 코드를 직접 짜야 이해되는 내용, 도구별 옵션, 설계 비교 |
| 2 입문 | 비전공으로 막 입과한 분 | 보고 따라 만들 수 있다 | 언어 기초 문법, 기술의 첫 사용법, 튜토리얼 수준의 실습, 왜 쓰는지 | 여러 기술을 엮는 설계, 성능 튜닝, 내부 구현 |
| 3 기초 | 변수·함수·조건문을 익힌 분 | 배운 것을 변형해 혼자 기능을 구현할 수 있다 | 기능 하나를 완성하는 데 필요한 개념, 비슷한 개념의 차이, 자주 하는 실수와 해결 | 대규모 운영, 내부 알고리즘 |
| 4 실전 | 웹 프로젝트를 만드는 분 | 설계를 골라 근거를 말하고 오류 원인을 찾을 수 있다 | 여러 기술의 연결, 설계 선택과 손익, 운영·배포·디버깅, 보안 | 기본 문법과 사용법, 논문 수준의 내부 구조 |
| 5 심화 | 전공자·실무 경험자 | 내부 동작과 손익을 근거로 판단하고 장애를 분석할 수 있다 | 내부 구현, 성능·확장성·보안의 손익, 표준 문서, 대안 설계 비교 | 사용법 입문, 튜토리얼 |

단계가 헷갈리면 두 가지를 묻는다.

1. 이 항목을 배우려면 무엇을 이미 할 줄 알아야 하는가?
2. 배우고 나면 무엇을 할 수 있는가? (위 표의 "배우고 나면"과 맞는 단계를 고른다)

## 중요도 기준

| 값 | 표시 | 뜻 |
|---|---|---|
| 1 | ★★★ 필수 | 모르면 AX 서비스를 만들다 막힌다 |
| 2 | ★★ 중요 | 자주 쓰고, 특정 기능을 만들 때 꼭 필요하다 |
| 3 | ★ 선택 | 특정 규모나 환경에서 필요하다 |

네 질문 중 "그렇다"의 수로 정한다. 3~4개면 필수, 2개면 중요, 0~1개면 선택이다.

1. **필수 경로:** 기획 → 화면 → 서버 → DB → LLM → 배포로 이어지는 AI 서비스 제작 경로에 들어가는가?
2. **바탕:** 다른 개념을 배우는 데 먼저 필요한가? (`stats`와 `check`가 선수 개념으로 쓰인 수를 함께 본다)
3. **위험:** 모르면 장애, 보안 사고, 큰 비용으로 이어지는가?
4. **수요:** 과정 교과목, 채용 공고, 기술 면접, 자격 기준, 공식 입문서에 자주 나오는가?

**순서:** 분야 파일 안에서 항목은 단계, 주제 먼저, 중요도 순으로 놓고, 같은 중요도 안에서는 먼저 배울 것을 앞에 둔다. 이 순서를 검사 도구가 지킨다. 단계별 사전의 "공부 순서"는 이 순서와 선수 개념으로 자동 생성한다. 같은 단계 안에서는 중요한 항목의 선수 개념이 그만큼 앞으로 당겨진다. 단계를 넘는 경우는 검사 도구가 경고한다.

## 쓰는 규칙

- 범위는 [기준 자료](sources.md)와 대조하되, 문장은 직접 쓴다. 다른 자료의 문장을 옮기지 않는다.
- 프로젝트나 대화에 묶인 표현을 쓰지 않는다. 검사 도구가 대표 표현을 막는다.
- 분야 경계: 테스트 일반은 `dev`, API 테스트는 `be`, 지표·추적·장애 분석은 `ops`, 캐시는 `db`가 맡는다. 다른 분야에 속하는 항목은 그 분야 파일에 둔다.
- 사전에 없는 개념을 만나면 후보로 모았다가 검토한 뒤 추가한다.

## 버전

`broad_names.json`에는 뜻이 여러 개이거나 어디에나 나오는 이름을 모은다. 후보를 찾을 때 세지 않으므로, 별칭을 더하거나 오탐을 만나면 이 파일도 함께 본다. 주제의 제목은 넣을 수 없다.

`build`는 `dist/`와 함께 스킬에 넣는 `skills/study-notes/catalog.json`도 만든다. 스킬은 폴더만 복사해 설치해도 돌아야 하기 때문이다. 항목을 고치면 `build`를 실행해 함께 커밋한다. 노트 검사 코드는 스킬의 `scripts/concepts.py`에 있다.

`VERSION`은 스킬 버전과 따로 올린다. 각 노트는 쓸 때의 사전 버전을 기록한다.

| 올리는 자리 | 언제 | 예 |
|---|---|---|
| 첫째 | id 체계처럼 호환이 깨질 때 | 1.0.0 → 2.0.0 |
| 둘째 | 항목을 추가하거나 단계·중요도를 바꿀 때 | 1.0.0 → 1.1.0 |
| 셋째 | 오탈자, 요약 다듬기, 링크 수정 | 1.0.0 → 1.0.1 |

0.x는 시범 기간이다. 전 분야를 채우고 검토를 마치면 1.0.0으로 올린다.
